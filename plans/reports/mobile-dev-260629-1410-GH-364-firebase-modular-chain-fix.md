## Problem

CI run 28354398748 (`fastlane beta` → `xcodebuild archive`) failed:
`error: Module 'FirebaseCore' not found` (FirebaseMessaging target). PR #190
gave only GoogleUtilities modular headers — enough to pass the `pod install`
static-lib check, NOT enough for the Release compile. In static-library mode
(CI builds without `use_frameworks!`) FirebaseMessaging compiles
`@import FirebaseCore;`, and FirebaseCore in turn `@import`s the rest of the
chain, so every pod in the `@import` cascade needs a clang module map.

## Fix — approach (b), targeted modular headers for the full Firebase chain

`ios/Podfile` — replaced the single `pod 'GoogleUtilities', :modular_headers => true`
with the full chain (kept fmt `post_install` patch + `$RNFirebaseAsStaticFramework`
intact):

```ruby
pod 'FirebaseCore', :modular_headers => true
pod 'FirebaseCoreInternal', :modular_headers => true
pod 'FirebaseCoreExtension', :modular_headers => true
pod 'FirebaseInstallations', :modular_headers => true
pod 'FirebaseMessaging', :modular_headers => true
pod 'GoogleDataTransport', :modular_headers => true
pod 'GoogleUtilities', :modular_headers => true
pod 'PromisesObjC', :modular_headers => true
pod 'nanopb', :modular_headers => true
```

Chose (b) over global `use_modular_headers!` to avoid RN-core/folly
non-modular-header conflict risk on RN 0.83. Lower blast radius.

`ios/Podfile.lock` — changed: yes (the 9 chain pods now recorded as explicit
DEPENDENCIES + new PODFILE CHECKSUM).

## SECOND blocker found by the real compile (NOT a pod_install thing)

This is exactly why a real compile was required. Once the Firebase compile was
fixed, the archive reached the resource-copy phase and failed:
`error: Build input file cannot be found: ios/GoogleService-Info.plist`.

Root cause: push-notif (#189) committed the plist to `ios/auxi/GoogleService-Info.plist`
(next to Info.plist) but its Xcode file ref used `path = "GoogleService-Info.plist"`
(resolves to `ios/`), unlike every sibling in the `auxi` group which uses
`path = "auxi/<file>"`. It was latent — the build never got past the Firebase
compile to hit it. Fixed the ref to `name = "GoogleService-Info.plist"; path = "auxi/GoogleService-Info.plist"`
in `ios/auxi.xcodeproj/project.pbxproj` (committed separately so it can be
dropped/reviewed independently).
