## Phase Boundary

**What this phase delivers:** A live `POST /api/v05/recommendation/next` endpoint backed by a Redis-stored session that cycles through 4 variation axes (SILHOUETTE → LAYERING → COLOR → NEW_ANCHOR), enforces anchor-pin + single-layer-swap invariants, and meets p95 < 250ms latency under 1-user load. The endpoint must be mergeable to the backend submodule by **2026-05-10** to unblock mobile work in Phase 3.

**What this phase does NOT deliver:**
- Mobile UI wiring (Phase 3)
- Telemetry events on the mobile side (Phase 3)
- V05 onboarding API (Phase 4)
- Foundational gates like CORS allowlist, JWT secret validation (Phase 2)
- Maestro E2E flows (Phase 5)

</domain>

## Implementation Decisions (locked from PRD)

### API Contract — `POST /api/v05/recommendation/next`

- **Request body** (locked):
  ```
  {
    session_id: string                    // required
    current_outfit_hash: string           // required, used to detect drift
    rejected_items?: string[]             // optional, item ids to exclude
    preferred_colors?: string[]           // optional, color hint
    style_feedback?: string               // optional, free-text from Edit Context
    force_variation_axis?: "SILHOUETTE" | "LAYERING" | "COLOR" | "NEW_ANCHOR"
  }
  ```
- **Response shape** (locked): same as `POST /api/v05/recommendation/build`, plus `trace.variation_axis: "SILHOUETTE" | "LAYERING" | "COLOR" | "NEW_ANCHOR"` to inform mobile axis-chip rendering.
- **Endpoint location** (locked): `wardrobe-backend/routers/v05_recommendation.py` — add `/next` alongside existing `/start` and `/build`.
- **Documentation** (locked): `wardrobe-backend/API_DOCUMENTATION.md` MUST be updated for `/api/v05/recommendation/next` as part of the PR (drift-prevention rule).

### Redis Session

- **Key format** (locked): `v05_recsess:{uuid}` — uuid generated by `/start`, persisted by mobile, sent on every `/next` call.
- **TTL** (locked): 1800 seconds (30 minutes).
- **Stored fields** (locked): `current_outfit`, `variation_stage` (1..4), `seen_item_ids` (set, no repeats across cycle), `anchor_id` (BT item id, frozen stages 1-3), `style_signals` (accumulator from `style_feedback` calls).
- **Session-expired behavior** (locked): server returns 404; mobile silently re-`/start` (mobile-side concern, but server contract must signal expiry distinctly from "session not found at all").

### 4-Axis Cycle (locked from PRD §3.1 + Decision Log 2026-05-08)

Order: **SILHOUETTE → LAYERING → COLOR → NEW_ANCHOR → restart at SILHOUETTE.**

| Stage | Axis | Handler behavior |
|---|---|---|
| 1 | SILHOUETTE | Swap L2 (top), keep BT/SH/L3 |
| 2 | LAYERING | Swap L3 (cold weather) OR SH (warm weather); pick by climate input |
| 3 | COLOR | Swap L2 to a different-color item (within style coherence) |
| 4 | NEW_ANCHOR | Full regen — pick new BT, build outfit from scratch |

**`variation_stage` increment** (locked): server increments after computing the swap; restart at 1 after stage 4.

**`force_variation_axis`** (locked): when present, server uses that axis regardless of stored `variation_stage`; does NOT increment `variation_stage` (forced-axis taps don't advance the auto-cycle).

### Invariants (HARD-FAIL — locked from PRD Decision Log)

- **Anchor pin (REMIX-BE-04)**: at stages 1, 2, 3, the BT (bottom) item must equal the session's stored `anchor_id`. If after axis handler the result differs, raise `AnchorPinViolation` and refuse to return outfit.
- **Single-layer-swap (REMIX-BE-05)**: at stages 1, 2, 3, exactly one layer (compared to `current_outfit`) must differ. If 0 or >1 layers differ, raise `SingleLayerSwapViolation`.
- **Stage 4 (NEW_ANCHOR)**: invariants do not apply — full regen is expected to differ on multiple layers including BT.

These invariants are enforced **after** axis handlers execute, before the response is built. Hard-fail = 500 with structured error code so QA logs can grep them.

### Pre-Filtering Pool (REMIX-BE-06, locked)

Candidate pool filtered by:
- **Climate**: weather/temperature input from session start
- **Gender**: user gender from session
- **Formality**: ±3 from anchor's formality score
- **Weight (item physical weight)**: ±2 from anchor's weight class
- **Color-temperature**: warm/cool match
- **Fit-contrast**: respect fit pairing rules from V2 `_pre_filter_for_anchor`

Source pattern to port: `wardrobe-backend/blueprints/recommendation/engine_v2.py:486` (`_pre_filter_for_anchor`).

### Tests (REMIX-BE-07, locked)

Required test coverage for unit suite (`pytest -m unit`):
- 4-axis state transitions (SILHOUETTE → LAYERING → COLOR → NEW_ANCHOR → restart)
- Anchor-pin enforcement (stages 1-3)
- Single-layer-swap enforcement (stages 1-3)
- `seen_item_ids` no-repeat across a single cycle
- `force_variation_axis` overrides without advancing stage
- Session expiry (TTL elapsed → 404)
- Edge cases: pool exhausted (only 1 candidate left), empty rejected_items, invalid session_id

Mock Redis (do NOT hit real Redis in unit tests). Use existing test fixtures in `wardrobe-backend/tests/conftest.py`.

### Performance (REMIX-BE-08, locked)

- p95 `/next` latency **< 250ms** under 1-user load (single-user benchmark, not concurrent load).
- Measure with pytest-benchmark or equivalent — fail the test if p95 exceeds.
- This includes Redis GET/SET + axis handler + invariant checks. Does NOT include LLM calls (NEW_ANCHOR Phase-2 stretch only).

### Claude's Discretion

- **Module organization**: PRD references `engine_v05_variation.py` and `recommendation_session_v05.py` as new files. Planner may split or combine, but must keep `engine_v05.py` clean and not entangle V2 patterns.
- **Error code naming**: `AnchorPinViolation`, `SingleLayerSwapViolation` are placeholder names — planner picks final identifiers consistent with existing exception class style.
- **Redis client choice**: use existing `wardrobe-backend/utils/redis_client.py` if present; otherwise wire one matching backend conventions (no new dependency).
- **Pool size threshold**: spec says "skip exhausted axes silently, advance to next" but exact threshold (e.g., < 2 candidates → skip) is planner's call.

<specifics>

## Specific Ideas (from PRD)

- **Cross-fade animation 250ms** is mobile-side; backend p95 budget is independent of cross-fade.
- **Redis 30-min TTL** is acceptable per design — server returns 404 on expiry, mobile re-`/start` silently. Do NOT extend TTL or add refresh; this is an explicit design constraint.
- **`force_variation_axis` does not advance stage**: forced-axis call from mobile (long-press picker) is a one-off, not a redirect. The auto-cycle continues from where it was on the next non-forced tap.
- **NEW_ANCHOR (stage 4)** triggers a 1.5s mobile cooldown — backend doesn't need to enforce, but the response should be small enough to render before the cooldown ends.

</specifics>
